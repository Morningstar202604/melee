- 版本：v1.0

- 配套原型：`out/broadcast-ui-mockup.html`（可点击，非静态图）

## 0. 这份文档回答什么

不是"用什么框架"，而是：

1. 观众打开网页第一眼看到什么。
2. 每个区域放什么、为什么放这里。
3. 用户能做哪些操作、点了之后发生什么。
4. 比赛在进行、暂停、回放、结束时，界面分别长什么样。

设计对象是**一个看比赛的人**，不是开发者，也不是参赛模型。

---

## 1. 五条设计原则

### 1.1 三秒法则

任何时刻，观众扫一眼必须能回答四个问题：

1. 谁在打？
2. 打到哪了？
3. 谁领先？
4. 秘密是什么（观众独有的信息优势）？

答不出来就是设计失败。这四件事分别对应：选手卡、顶栏轮次、比分数字、秘密牌。

### 1.2 舞台优先，仪表盘靠边

观战页的主体是一块固定的 16:9 舞台，不是一个由卡片拼起来的后台。所有构图在舞台内完成，页面不滚动。仪表盘（榜单、历史）放在别的页面，不进舞台。

### 1.3 状态永远可读

领先不能只靠颜色，必须同时有数字与文字。任何一次状态变化都要有可见的因果：谁做的、做了什么、结果是什么。观众不应该需要读日志才能理解局面。

### 1.4 等待也是内容

模型思考的几秒钟是这类产品最大的敌人。界面必须把等待变成内容：思考流可见、倒计时可见、可能性空间在收窄、押注在跳动。绝不允许出现"画面静止且没有任何反馈"超过 3 秒。

### 1.5 回放与直播同构

直播是"事件流的最新位置"，回放是"事件流的某个位置"。两者共用同一套画面，只换时钟。不另做一个"回放页"。

## 2. 信息架构

### 2.1 站点地图

```
/                        大堂：正在直播、今日赛程、积分榜摘要
/m/:matchId              观战：直播 / 回放（同一页，两种时钟）
/m/:matchId/recap        战报：结果、一句话、转折点、高光、分享
/p/:playerSlug           选手档案：身份、战绩、交手记录
/season/:seasonId        赛季榜：积分、排名、赛程
/schedule                赛程日历
/director/:matchId       导播台（内部，不对外）
```

### 2.2 三种进入方式

| 用户 | 入口 | 第一需求 |
|---|---|---|
| 路过的人 | 分享链接 / 首页推荐 | 30 秒内看懂在发生什么 |
| 追赛季的人 | 赛程提醒 / 收藏 | 直接进直播，看押注与排名 |
| 赛后补看的人 | 战报页 / 高光视频 | 快速知道结果与名场面 |

### 2.3 信息优先级

| 级别 | 内容 | 位置 |
|---|---|---|
| P0 | 比分、轮次、当前动作、秘密 | 舞台中央与顶栏 |
| P1 | 思考流、解说、时间轴 | 选手卡与下三分之一 |
| P2 | 押注、观众数、分享 | 底栏 |
| P3 | 模型参数、历史战绩 | 档案页，不进直播 |

### 3.1 分区图（1920×1080 设计稿）

```
┌──────────────────────────────────────────────────────────────────────┐
│ 顶栏 64                                                              │
│ 赛季 · 第 3 场        第 5 问 / 21            ● LIVE   1,284 人     │
├───────────────┬──────────────────────────────────┬───────────────────┤
│               │  秘密词（仅观众可见）             │                   │
│   选手 A      │  ┌────────────────────────────┐  │      选手 B       │
│   灰隼        │  │          灯 塔             │  │      砚台         │
│               │  └────────────────────────────┘  │                   │
│   5 问        │                                  │      4 问         │
│   领先        │  可能性空间  14 → 1              │      落后         │
│               │  [灯塔][航标][路灯][钟楼]...     │                   │
│   思考中      │                                  │      思考中       │
│   内心戏      │  当前提问                         │      内心戏       │
│   问答账本    │  它会发光吗？          [ 是 ]     │      问答账本     │
├───────────────┴──────────────────────────────────┴───────────────────┤
│ 解说条 96   灰隼连问三个"是"，方向已经锁定在海边。                   │
├──────────────────────────────────────────────────────────────────────┤
│ 时间轴 56   ●──────────────○───────────────  1x   ⏮  ⏭   回到直播  │
├──────────────────────────────────────────────────────────────────────┤
│ 控制条 72   ▶ 暂停   0.5x 1x 2x   上帝视角   │ 押注：谁先猜中？      │
│                                              │ [灰隼 1.8] [砚台 2.1] │
└──────────────────────────────────────────────────────────────────────┘
```

栅格：左右各 424，中间自适应；间距 40；外边距 48。

### 3.2 各区域职责

| 区域 | 尺寸 | 职责 | 不允许放什么 |
|---|---|---|---|
| 顶栏 | 64 | 赛事身份、进度、直播状态、在线人数 | 导航菜单、设置项 |
| 选手卡 | 424×792 | 身份、已用问题、状态、内心戏、账本 | 模型参数、历史数据 |
| 秘密牌 | 896×112 | 观众独有的信息优势 | 选手可见的任何内容 |
| 可能性场 | 896×304 | 把"接近答案"变成可见的收窄 | 精确概率（除非真算过） |
| 当前提问 | 896×164 | 此刻正在发生什么 | 多条历史（历史在账本） |
| 解说条 | 全宽×96 | 一句话解释刚才发生了什么 | 判定结果、比分 |
| 时间轴 | 全宽×56 | 位置、回放、变速 | 弹幕、评论 |
| 控制条 | 全宽×72 | 播放控制 + 押注 | 分享、设置（放战报页） |

### 3.3 为什么这样排

- **秘密牌在正上方**：观众的信息优势是这类节目的核心快感来源，必须占据视觉顶点。它同时解释了两侧选手为什么这样问。
- **选手面对面**：左右分栏模拟"对峙"，中间是战场。不是并列的聊天窗口。
- **内心戏在选手卡内**：思考属于这个人，不该飘在中央抢戏。关键时刻由导播把它展开。
- **解说在下三分之一**：电视字幕位。它解释，不主导。
- **押注在最底**：参与感要有，但不能盖过比赛。

## 4. 核心组件规格

### 4.1 选手卡

```
┌─────────────────────────────┐
│ [A]  灰隼                   │  ← 头像字母块 + 角色名
│      claude-sonnet-4.6  ·   │  ← 模型标识（小字）
│                     思考中  │  ← 状态芯片
│                             │
│  5  问        领先            │  ← 大数字 + 相对位置
│                             │
│  内心戏                     │
│  发光、固定、远距可见、水边。│  ← 最新一行，可展开
│  只剩灯塔。                  │
│                             │
│  问答账本                   │
│  01 会发光吗？        是    │
│  02 固定不动吗？      是    │
│  03 给远处的人看？    是    │
│  04 建在水边吗？      是    │
└─────────────────────────────┘
```

规则：

- 状态芯片只有四种：`思考中 n.ns`、`等待`、`已提交`、`犯规`。
- 大数字是"已用问题数"，不是分数。领先/落后用文字加箭头方向，不只靠颜色。
- 内心戏默认显示最新一行，点击展开完整流；展开状态在本次会话内记住。
- 账本只显示最近 6 条，自动滚到最新；点击任意一条跳到该事件回放。
- 犯规时卡片边框转红一次（200ms），状态芯片显示"犯规"，账本记录原因。

### 4.2 秘密牌

- 观众可见时：大字号显示秘密本身，附一行"仅观众可见"。
- 选手视角时：整块替换为遮罩文字"已隐藏 · 选手视角"，并显示当前视角是谁。
- 切换动画 240ms，不做翻转特效（会喧宾夺主）。

### 4.3 可能性场

- 一屏最多 16 个候选词，网格排列。
- 每产生一次有效回答，被排除的词划掉并降透明度，保留 400ms 动效。
- 顶部显示 `14 → 1` 的收窄进度。
- 若游戏无法枚举候选（如狼人杀），此区域替换为"已知事实板"：已确认的身份、已排除的玩家。

### 4.4 当前提问

- 大字显示问题原文，右上角显示判定印章：`是` / `否` / `不知道` / `猜中`。
- 判定印章有 600ms 的落章动画；这是全场最重要的节奏点。
- 未回答时显示三个点的等待动画与剩余思考时间。

### 4.5 解说条

- 左侧标签"解说"，右侧一句话，不超过 40 字。
- 每句话带 `refs`，点击可跳到对应事件。
- 解说只描述已发生的事实；数字与动作名必须能在事件里找到，否则整句丢弃。
- 解说与判定严格分离：解说永远不说"他赢了"，只说"他报出了答案"。

### 4.6 时间轴

- 一条主轨，事件以小刻度表示；关键事件（猜中、犯规、揭晓）用大刻度。
- 拖动即进入回放，轨道颜色由红（直播）变琥珀（回放）。
- 悬停刻度显示该事件摘要。
- 右侧固定三个控件：倍速、上一事件、下一事件。
- 处于回放时，右上角出现"回到直播"按钮。

### 4.7 押注条

- 只在比赛进行中且未结算时出现。
- 一句话问题 + 两个选项 + 当前赔率 + 倒计时。
- 点击后按钮变为"已押 10 积分"，不可撤销。
- 结算时在战报页展示结果，不在舞台上弹窗。

### 4.8 揭晓层

- 用于关键信息揭示（猜中、身份公开、终局）。
- 全屏半透明遮罩 + 中央大字，600ms 入场，1.6s 停留。
- 可被"跳过动画"设置关闭。

### 4.9 终局卡

- 比赛结束后 1.2s 出现，不从侧面滑入，直接在舞台中央浮现。
- 内容：胜者、关键数字（几问终结）、一句话战报、两个按钮（看回放 / 分享战报）。
- 不自动跳转，观众自己决定。

## 5. 交互状态机

| 状态 | 触发 | 画面表现 | 可执行操作 |
|---|---|---|---|
| `live.thinking` | 直播中，选手思考 | 状态芯片计时，当前提问区三点动画 | 暂停、押注、切视角 |
| `live.answered` | 判定落下 | 印章动画 600ms，可能性场收窄 | 暂停、押注 |
| `live.reveal` | 关键事件 | 揭晓层 1.6s | 跳过 |
| `live.ended` | 终局 | 终局卡浮现 | 看回放、分享 |
| `paused` | 点暂停 | 画面定格，顶栏显示"已暂停" | 继续、拖动、切视角 |
| `replay` | 拖动时间轴 | 轨道转琥珀色，显示"回放中" | 变速、跳事件、回到直播 |
| `reconnecting` | SSE 断开 | 顶栏转黄，显示"重连中 3s" | 无（自动重试） |
| `error` | 重连失败 | 顶栏转红，显示"信号中断" | 刷新、看战报 |

状态转换规则：

- 任何状态下拖时间轴 → `replay`。
- `replay` 下点"回到直播" → `live`，位置跳到最新。
- `live.ended` 不自动进入 `replay`，避免打断情绪。
- `reconnecting` 期间画面保留最后一帧，不黑屏。

## 6. 功能怎么用

### 6.1 首次进入：60 秒看懂

| 时间 | 用户看到 | 系统在做什么 |
|---|---|---|
| 0s | 舞台直接出画面，比赛已在进行 | 自动连到直播流，不要求登录 |
| 3s | 秘密牌高亮一次，旁边浮出"只有你看得到" | 一次性引导气泡，3 秒后自动消失 |
| 10s | 一次提问落下判定，可能性场划掉五个词 | 演示"因果" |
| 25s | 底栏出现押注条 | 第一次可参与 |
| 45s | 解说解释当前局势 | 建立"有人在讲"的预期 |
| 60s | 引导结束，不再出现任何气泡 | 记忆到本地，不重复打扰 |

引导只有三条，不弹窗、不遮画面、不要求点击"下一步"。

### 6.2 看直播

1. 从大堂点正在直播的卡片。
2. 进入观战页，自动播放。
3. 想细看某一步：点选手账本里的任意一行，跳到那一步（自动进入回放）。
4. 看完点"回到直播"。
5. 想换视角：点选手头像，进入该选手视角（秘密被遮，只看到他的观察）。

### 6.3 回看

1. 拖时间轴到任意位置。
2. 用上一事件 / 下一事件逐帧看。
3. 倍速 0.5x / 1x / 2x / 4x。
4. 点"回到直播"恢复。

### 6.4 押注

1. 底栏出现问题时点击一个选项。
2. 按钮变为"已押 10 积分"，倒计时继续。
3. 结算在战报页，不在舞台弹窗。

### 6.5 分享

1. 终局卡点"分享战报"。
2. 进入战报页，生成一张 16:9 海报（结果 + 一句话 + 关键一步）。
3. 复制链接或下载图片。

### 6.6 追赛季

1. 大堂看积分榜摘要。
2. 点选手进档案，看战绩与交手记录。
3. 关注后，下一场开赛前收到提醒（站内，不做推送）。

## 7. 选手视角（差异化功能）

这是竞品没有的交互，成本极低（服务端已有 `observe(state, player)`）。

| 视角 | 看到什么 |
|---|---|
| 上帝视角（默认） | 秘密、双方完整账本、可能性场 |
| 选手 A 视角 | 秘密被遮，只看得到 A 自己的账本与公开提问 |
| 选手 B 视角 | 同上，镜像 |

用途：

- 观众可以亲自体验"信息不对称"，理解选手为什么会犯错。
- 回放时切换视角，能看清"这一问在当时是否合理"。
- 也是内容素材：截图对比"观众知道的 vs 选手知道的"。

切换方式：点选手头像，或按 `1` / `2` / `G`。

## 8. 移动端

| 断点 | 布局 |
|---|---|
| ≥1440 | 完整舞台，左右选手卡 |
| 1024–1439 | 舞台等比缩小，选手卡变窄，账本只显示 4 条 |
| 768–1023 | 舞台在上，选手信息折叠为两个标签页 |
| <768 | 舞台 16:9 置顶，下方四个标签：解说 / 内心戏 / 账本 / 押注 |

移动端原则：

- 舞台永远 16:9 完整可见，不裁切。
- 押注固定在舞台下方，不悬浮遮挡。
- 时间轴在移动端变为"进度条 + 上一事件 / 下一事件"，不做精细拖动。

## 9. 键盘与无障碍

| 键 | 作用 |
|---|---|
| `Space` | 暂停 / 继续 |
| `←` / `→` | 上一事件 / 下一事件 |
| `L` | 回到直播 |
| `G` | 切换上帝视角 |
| `1` / `2` | 切换选手视角 |
| `Esc` | 退出回放 / 关闭弹层 |

无障碍要求：

- 所有状态变化同时有文字，不只靠颜色。
- 动效遵循 `prefers-reduced-motion`，关闭编排动画与揭晓层。
- 解说条是 `aria-live="polite"`，比分变化是 `aria-live="assertive"`。
- 对比度：正文 ≥ 7:1，次要文字 ≥ 4.5:1。
- 所有可点击区域 ≥ 44×44。

## 11. 文案规范

### 11.1 解说

- 一句话，不超过 40 字。
- 只描述事实，不给判定。
- 禁止形容词堆砌，禁止"精彩""震撼"。
- 示例：
  - 好："灰隼连问三个'是'，方向已经锁定在海边。"
  - 差："灰隼表现非常精彩，展现了强大的推理能力。"

### 11.2 战报一句话

- 结构：`第 N 问，答案。` 或 `双方都没猜中，秘密是 X。`
- 示例："第 5 问，灯塔。" "砚台在第 4 问停住，秘密是钟楼。"

### 11.3 空状态与错误

| 场景 | 文案 |
|---|---|
| 今晚无比赛 | 今晚没有排期。下一场 20:00，两位选手已经在候场。 |
| 直播未开始 | 20:00 开赛。现在可以先看上一场的 30 秒高光。 |
| 重连中 | 信号中断，正在重连（3s）。画面会停在最后一帧。 |
| 比赛已回收 | 这场比赛的直播流已结束。战报和回放仍然可以看。 |
| 押注已关闭 | 这一问已经结束，下一问开始时可继续押。 |

## 12. 界面不做的事

| 不做 | 原因 |
|---|---|
| 舞台内嵌聊天室/弹幕 | 抢解说位，且需要审核成本 |
| 舞台内显示排行榜 | 与当前比赛无关，分散注意 |
| 设置面板 | 直播场景没有耐心配置；设置放个人页 |
| 自动播放音效 | 浏览器会拦，且吓人 |
| 弹窗式引导 | 打断观看；用气泡，3 秒消失 |
| 全屏 loading 骨架 | 直接出最后一帧或大厅预览，不空屏 |
| 无限历史滚动 | 舞台只显示当前，历史交给时间轴 |

## 13. 验收清单

界面部分验收（可逐条测试）：

1. 1280×720、1920×1080、2560×1440 三种宽度下，舞台不变形、不裁切、不滚动。
2. 任意时刻截图，能在 3 秒内读出：谁在打、打到哪、谁领先、秘密是什么。
3. 从直播拖到回放再回到直播，画面与事件完全对齐，不跳帧、不重复。
4. 断网 10 秒，画面保留最后一帧，恢复后不丢事件。
5. 点击账本任意一条，能跳到对应时间点，且解说同步。
6. 切换选手视角后，秘密与对手账本被遮，且不会通过网络请求泄漏（前端不做安全判断，服务端过滤）。
7. 押注后按钮不可重复点击，倒计时结束自动关闭。
8. 键盘 6 个快捷键全部可用，焦点可见。
9. 开启"减少动态效果"后，无编排动画与揭晓层，信息不丢失。
10. 移动端 390×844 下，舞台完整可见，押注不遮挡，四个标签可切换。

## 14. 与原型的关系

`out/broadcast-ui-mockup.html` 实现了：

- 观战页完整布局与上述九个组件。
- 直播播放、暂停、时间轴拖动、回到直播、倍速。
- 上帝视角 / 选手视角切换（切换后秘密牌与对手账本立即遮蔽）。
- 内心戏逐字打字效果、账本点击跳转、选手判断面板、出手节奏条、提问历史条。
- 押注交互、终局卡、节奏柱状图。
- 大堂（含赛季积分榜 + 赛制说明）、战报（含三个瞬间 + 节奏图）、选手档案（含交手记录 + 提问分布）三个辅屏。

原型里可以验证的交互：

| 操作 | 结果 |
|---|---|
| 空格 | 暂停 / 继续 |
| ← / → | 上一个 / 下一个事件，自动进入回放 |
| 拖时间轴 | 进入回放，轨道转琥珀色，出现"回到直播" |
| 点账本任意一行 | 跳到该提问结束的那一刻 |
| 点选手头像区域下方视角按钮 / 按 1、2、G | 切换上帝视角与两个选手视角 |
| 点押注选项 | 按钮变绿并锁定，显示"已押 10 积分" |
| 比赛结束 | 终局卡浮现，可选"看战报"或"从头回放" |
| 地址栏加 `#lobby` / `#recap` / `#profile` | 直接打开对应屏幕（截图与评审用） |
