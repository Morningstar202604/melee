# 路线图

原则：只列**有明确验收标准**的项，不写"持续优化"这种无法判断的句子。
已完成项移到 [CHANGELOG](../CHANGELOG.md)。

## 下一版（1.1）

| 项 | 为什么做 | 验收标准 |
|---|---|---|
| 事件流 `visibility` 落地 | 契约里已有字段但未使用，隐藏信息目前只在 `observe()` 裁剪 | 至少一条事件带 `visibility: {players:[...]}`，SSE 对非授权观众不发送，测试覆盖 |
| 单场 token 预算与熔断 | 免费额度会 429，当前只有 2 次重试 | 单场超过 token 上限时自动结束并写 `match.ended`，reason 说明原因 |
| 在线人数跨副本聚合 | 多副本下各报各的 | Redis 模式下 `viewers` 为全局值，两副本联调验证 |
| `/archive` 全文搜索 | 赛事多了以后只能按赛制筛选 | 支持 `q=` 匹配选手名与 matchId，200 场下 < 100ms |

## 1.2

| 项 | 为什么做 | 验收标准 |
|---|---|---|
| 赛制扩到 10+ | 内容量决定留存 | 新增至少 4 个确定性赛制，每种都有解说/镜头/战报 |
| 账号体系（可选） | 静态 token 不是多租户 | 引入 OIDC，token 模式仍保留 |
| 高光模板 | 当前高光画面是固定版式 | 至少 3 套版式，可通过查询参数选择 |
| 移动端导播 | 导播台目前只适配桌面 | 390px 下可完成选台与切镜 |

## 明确不做

| 不做 | 原因 |
|---|---|
| 匿名对战 + 人投票 + 全站 Elo | FastChat（39.5k★）已占位，且与角色叙事冲突 |
| 110 个赛制 | TextArena 是评测基础设施，不解决"怎么播" |
| 自研 LLM 主持型赛制 | 破坏确定性判定与可复现性 |
| 引入 React / Vite | 零构建是产品约束；`view.js` 的 reducer 可原样迁移 |
| 多租户 SaaS / 计费 | 边界之外；需要时应交给网关或 IdP |

## 已知但暂不修

| 项 | 现状 | 影响 |
|---|---|---|
| 分支覆盖率 81.6% | 未覆盖集中在外部依赖失败路径 | 需要真实故障注入，性价比低 |
| 变异测试抽样 | Windows 上 `mutmut` 无法启动（缺 `resource`） | 只有 AST 级抽样结果 |
| 多副本事件日志 | SQLite 单文件，需要共享存储 | 多副本部署时须把 DB 放在共享卷 |
| Firefox / Safari | 只用 Chromium 验证过 | `EventSource` 与 `aspect-ratio` 行为未实测 |
