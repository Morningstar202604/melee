**当前风险**

- 3D 依赖 WebGL；无 GPU、禁用 WebGL 的环境只能进入明确的降级提示，不能宣称“所有浏览器都能开 3D”。
- `arena3d.html` 的 import map 使用 CSP `sha256` 白名单；改 import map 必须同步改 `services/match/api.py` 的 hash，否则脚本会被 CSP 拦截。
- 教练席只在真实直播、非导入场次开放；导入回放不允许改写历史。
- 1.10.2 已发布；新增提交必须先跑门禁，再移动/追加 tag 并五平台同步。

## 四、迭代规划路线图

### 1.10.2 — 思考流完整阅读与增量时序（2026-11-24）

- 3D 时序改为 20 条有界增量缓存，思考更新不重建 play-by-play。
- 长思考增加「展开全文」，展开后取消两行截断并可滚动阅读。
- 结构化动作统一格式化，不再出现 `[object Object]`。

### 1.10.1 — 思考流深挖（2026-11-24）

- 思考流：`thought.delta` 按选手/回合累计，2D 选手卡与 3D 追踪面板显示完整思考。
- 3D 追踪：新增 AI 思考流与对话/动作时序双轨，教练送达、回合、落子按 seq 排列。
- 直播本地化：`/events` 与 `/stream` 显式携带 `lang`，SSE 后续事件不会回退英文。

### 1.10.0 — 观赛与教练

- 提示词协议层：按赛制注入目标、约束、输出 JSON 契约；未知赛制安全回退。
- 教练席：直播中 `POST /matches/{id}/coach`，队列、去重、一次性投递、`coach.message` 事件、2D/3D UI。
- 3D 赛场：Three.js + OrbitControls，事件流驱动，镜头预设/自由镜头/自动环绕，无棋盘赛制全息舞台，WebGL 失败降级。
- 压力脚本：12 赛制并发、超时与卡死统计，报告落盘。
- 文档：本基线 + 行业调研 + API/部署/状态/README 更新。

### 1.11.0 — 可靠性与规模化

- 队列租约、重试、死信与可观测性；长对局断点恢复。
- SSE 背压与事件分页；大棋盘/长赛事的渲染 LOD。
- 多副本一致性、Redis 广播故障演练。

### 2.0.0 — 赛事级平台

- 多赛场/多桌并发与赛程编排；战队与赛季运营。
- 3D 场景资产管线与可配置舞台；裁判/教练多角色权限。

## 五、开源溯源与复用边界

| 来源 | 版本/许可证 | 在本项目中的位置 | 复用范围 | 不做什么 |
|---|---|---|---|---|
| FastAPI / uvicorn / Pydantic | 见 `NOTICE`，MIT/BSD | `services/match/` | HTTP、校验、ASGI | 不把业务规则交给框架 |
| sse-starlette / jsonschema / fastjsonschema | 见 `NOTICE` | SSE、事件契约 | 传输与校验 | 不另造事件协议 |
| lit-html | 3.3.3，BSD-3-Clause | `apps/web/vendor/lit-html.js` | 零构建模板渲染 | 不引入前端框架/打包器 |
| three.js | 0.187.0，MIT | `apps/web/vendor/three/` | 3D 场景图、材质、相机、WebGL 渲染 | 不引入游戏引擎；不改第三方源码 |
| OrbitControls | 0.187.0，MIT | `apps/web/vendor/three/addons/controls/OrbitControls.js` | 镜头拖拽/缩放/平移 | 不替代自有镜头预设逻辑 |
| TextArena | 0.7.4，MIT，可选 | `services/match/engine/` 适配层 | 确定性赛制环境 | 不作为运行时强依赖；不改上游规则 |
| python-chess | GPL-3.0，仅测试 | `services/match/tests/` | 读回 PGN 验证 | 不进运行时/镜像 |
| Kaggle Game Arena 数据 | CC BY 4.0 | 导入示例/演示库 | 真实对局样本与来源标注 | 不把数据集当自有内容转售 |
| HELM / OpenCompass / Artificial Analysis / PettingZoo / Werewolf Arena / Three.js 文档 | 仅调研引用 | `docs/RESEARCH-2026-11-24.md` | 方法论、竞品对标、技术可行性 | 不复制其代码或界面 |

**原则**：第三方只提供底层能力，必须通过适配层接入；核心事件流、观赛 reducer、教练队列、赛制协议由本项目自己维护。新增运行时依赖必须在同一提交更新 `NOTICE`，并跑许可证门禁。

## 六、变更纪律

1. 先改事件契约，再改 reducer/UI/测试；契约不通过不合并。
2. 任何“已交付”必须有远程提交、tag、门禁日志和演示包四件套。
3. 导入回放与真实直播共用渲染链路，但教练写操作只对真实直播开放。
4. 3D 是表现层，不是第二套真相；所有棋盘/选手/解说必须能从事件流重算。
5. 发布前跑 `bash scripts/verify_all.sh`，并保存原始日志到演示包 `validation.txt`。
