一、架构总览

分层清晰：页面（Next 16 App Router）→ 10 条 API 路由（全量安全收口）→ lib/battle 编排层（runner / registry / ratelimit / ui-stream / events）→ 五个领域 lib（arena 赛制、judge 裁判、sandbox 沙箱、providers 模型接入、db 数据）。对战进行中状态只活在进程内存（BattleHandle 注册表：事件日志 + pub/sub + AbortController），SQLite 只存终态战报与落库证据；断线靠 SSE 事件日志 + Last-Event-ID 重放，终态 60s 宽限期内迟到连接仍可全量重放，宽限后 handle 回收、战报永久可读。

二、赛制与隔离设计

定性结论（docs/audit/2026-10-13-orchestration-and-isolation.md）：本项目是确定性控制流的 workflow，不是 agent 框架场景——谁在第几轮对谁说话由代码规定，模型无权改变（赛制的信任锚点）。因此不引入 LangGraph / Mastra / AutoGen / Temporal 等框架，而是把框架级编排模式逐条对齐实现（Orchestrator–Worker、轮内 Parallel、Pipeline 多轮、Supervisor 裁判、确定性环境沙箱、zod 事件 Blackboard、rAF 背压、失败与预算隔离）。

三、安全姿态

安全是本仓最重的工程面，2026-10-15 收口批次对 14 条路由做了全量扫描，10 项发现全部修复并留行为锁。三条最值得注意的证据链：

  • XFF 防伪造：直接取 x-forwarded-for 首段可无限轮换绕过限流（实测 10/10 通过）。修复为 MELEE_TRUSTED_PROXY_HOPS（默认 1，append 型反代）取链尾第 N 项，行为锁 'bogus, 1.2.3.4' → 1.2.3.4。
  • 请求体放大：chunked 编码可绕 content-length 做内存放大；readJsonCapped 双路径封死（声明超限即 413，未声明边读边计数、超限 cancel + 413）。
  • 安全头不变式：不加 helmet，手写 CSP/HSTS/nosniff/XFO/Referrer-Policy/Permissions-Policy；SSE 与手写 Response 会绕过 Next 默认响应，故 hardenResponse 重建保留流与状态；一条测试遍历 9 条路由断言 nosniff+CSP+X-Frame-Options 齐备（lib/security.test.ts:48）。
上线闸门（spec §6.2 明文）：WASM 沙箱是语言级隔离，弱于 OS 级。文档引用真实事故作锚点（Cohere Terrarium 沙箱逃逸 CVSS 9.3、n8n 两条、Grist-Core 环境泄漏），并立下硬规则：非 OS 级隔离（默认 Pyodide 后端）不得公网暴露；接 Judge0 CE 后战报隔离级别自动升为"混合"。这条与"翻车即内容"的产品定位并存——观赏的是真实发生的事，没有的事必须明说。

四、数据层与前端状态

SQLite（node:sqlite）
6 表：battles / contestants / votes / predictions / judgements / sandbox_results。WAL + 写队列串行 + 建战事务。旧库用 PRAGMA table_info 探测缺列自动 ALTER（reasoning_text 迁移）。
battle-store（zustand）
rAF 帧调度器合并高频事件（一帧一次提交），终态事件立即写、取消未提交帧；快照水合时未提交草稿不得覆盖快照；hard-code / chess 的胜负从快照重建。
lineup-store + prediction
persist v2 + 一次性旧格式迁移；Key 与阵容分流：persist 只写阵容，Key 仅存 sessionStorage（测试断言 persist 内容零 Key）。押注记录存 localStorage 并本地统计战绩；胜负口径：硬场/棋场按通过数，其余先人票、平票全算、再裁判定分。

BYOK 全链路：请求体里的 Key → 仅存活于本进程该场对战的生命周期 → 战报与日志全链 redact() → 客户端仅 sessionStorage 暂存、刷新即失忆。这是"无服务端账号体系"前提下做到的凭证最小驻留。

六、风险与有意保留的边界

项状态说明
限流状态为进程内存已知边界多实例部署会分裂、冷启重置；与"单实例演示"定位一致，升级路径已留（Redis 滑动窗口 / 平台层）。
全局容量帽 100 次/10s已知边界单源打满即全站 429；已有"3 次被拒 → 60s 封禁"缓和；上线需按真实流量重标定。
直连暴露时来源 IP 不可信部署约束必须置于代管 XFF 的反代之后并显式设 hops=1。
WASM 沙箱非 OS 级上线闸门文档明文：未接 Judge0 不得公网开放；战报面板自动披露隔离级别。
多进程 / 持久化内存注册表刻意不做WorkflowAgent 等框架级耐久方案被审计判定"需求出现再挂"，不预付成本；观赛断线已由事件日志重放覆盖。
暗色单主题产品选择"转播演播室"风格，五赛场各有专属色（#8b8ff5 / #67e8f9 / #fb7185 / #38bdf8 / #e0a458）。

七、结论

这是一个完成度很高的"赛事转播"型项目：184 条测试全部离线可跑（假 OpenAI / 假 Judge0 服务器 + MockLanguageModelV4），核心不变式（事件 id 单调、隔离矩阵、安全头、Key 零落盘）都钉死了行为锁；文档与代码演进同步（每篇审计附修复与验证证据），"能官方就官方"的选型纪律执行得非常彻底。主要保留项全部是有意识的范围决策（单实例、演示定位、二期官方挂载点已定位），不是技术债遗漏。若走向生产，三件事按顺序做：反代 + XFF 配置、限流上 Redis、沙箱上 Judge0。
