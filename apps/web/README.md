# 观战端（零构建）

一个静态页面，直接消费比赛服务的 SSE。没有打包器，没有框架，打开就能跑。

## 跑起来

```bash
# 终端 1：比赛服务
cd melee
python scripts/serve.py --port 8099

# 终端 2：静态页
cd melee/apps/web
python -m http.server 8088
```

打开：

```
http://127.0.0.1:8088/index.html?api=http://127.0.0.1:8099
```

- `api=` 指向比赛服务（跨端口需要，服务已开 CORS）。
- `match=` 直接打开某一场：`?match=m_xxxx&api=http://127.0.0.1:8099`。
- 不传 `match` 时会读 `localStorage` 里上次看的那场。
- 点「新开一局」会建一场双贪心选手的对局（每步 1.6 秒，为了看得清）。

## 交互

| 操作 | 效果 |
|---|---|
| 拖时间轴 | 进入回放，事件前缀重算画面 |
| 暂停 / 继续 | 回放模式下暂停推进 |
| 从头回放 | 从第 0 条事件重新播放 |
| 回到直播 | 跳回最新事件并继续接收 SSE |
| 倍速 | 0.5x / 1x / 2x / 4x |
| 打开 | 输入 matchId 直接连 |

## 结构

```
index.html      舞台布局与样式（16:9，等比缩放）
src/view.js     事件 → 视图（纯 reducer，直播与回放共用）
src/sse.js      EventSource 封装 + REST 拉取
src/main.js     渲染与交互
```

## 为什么没有用 React

播放器的状态是"一串事件 + 一个游标"，纯 reducer 足够；
DOM 更新只在事件到达或游标移动时发生，频率跟 SSE 走，不在动画帧里重渲染。
引入框架会增加构建链，但不会让画面更好看——好看来自排版、节奏和镜头，不是来自组件树。

如果后续要做导播台、赛季页、复杂的表单，再按计划文档的 `apps/web` 方案迁到 React + Vite。
届时 `src/view.js` 的 reducer 可以原样搬过去。

## 看不到画面时的排查

1. 浏览器控制台有没有 CORS 报错 → 检查 `api=` 参数与服务是否启动。
2. 顶栏连接状态显示「重连中」→ 比赛可能已结束且未开 SSE 长连（正常，事件仍可回放）。
3. 画面全空但事件数在涨 → 刷新页面，`view.js` 的 reducer 与事件类型可能不同步。
